# 2026-11-18: M2, game feel

**Goal:** make moving tiles feel good, without slowing input or breaking the engine's purity.

**Design problem:** the engine stores tile values per cell, but a slide animation needs tile *identity* (this tile moved from here to there). I did not want animation concerns inside the rules, so:
- The engine gained one small output, `shifts` (where every tile went). Two shifts share a destination when tiles merge.
- `client/tiles.ts` turns those shifts into tiles with stable ids. It is pure TypeScript, so it is unit tested without a browser. A fuzz test plays 25 random games and checks after every move that the live tiles equal the engine grid exactly, no two share a cell, and ids stay unique.

**Rendering:** empty cells are a static backdrop. Tiles sit in a layer above and are positioned with a CSS `transform`, so a move is a transition the browser can run on the GPU, and React only changes two custom properties per tile. A merge is shown as two tiles sliding together, then vanishing under one new tile that pops in after the slide finishes (animation delay equals slide time). Scale animations live on an inner element so they don't fight the positioning transform.

**Input:** moves fire on keydown and apply immediately. Animations never block input, so the "input buffering" idea from the plan turned out unnecessary: there is no lock to buffer around. A rapid-fire run of 273 key presses with no pauses ended cleanly.

**Sound:** synthesized with the Web Audio API (square and triangle waves), no files. Merge pitch walks up a pentatonic scale with the tile value, so fast chains of merges never sound dissonant. The pitch function is unit tested. The audio context is created on the first sound, which always follows a key press or click, so browser autoplay rules are met.

**Accessibility and settings:** Sound and Motion toggles persist locally. Motion defaults to the OS "reduce motion" preference and, when reduced, turns off every animation, transition and the shake. Toggle buttons use `aria-pressed` and 44px touch targets.

**Verified in the browser:** zero misaligned tiles over 60 spaced moves and a full rapid game; merge fading tiles are always cleaned up; one merge of 256 triggers exactly one shake, and none when motion is reduced; reduced motion sets transition time to 0; no console errors.

**Mistakes caught along the way**
- The settings toggles first saved to storage inside a React state updater. Updaters must be pure (React can call them twice), so persistence now happens outside.
- My first shake test used mashed input and saw zero shakes: React batches many state changes into one render, so only the last move's effect fired. Real players press keys slower than a frame, so this is a test artifact, but it is worth remembering for the AI opponent, which can move fast.

**Not verified:** I can't hear audio in this environment. The pitch maths is tested and the sounds trigger without errors, but the actual sound quality needs a human ear. Please listen and tell me what to tune.
